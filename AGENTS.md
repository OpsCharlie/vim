# Neovim Config (lazy.nvim)

## Architecture

```
init.lua                  # Entrypoint — bootstraps lazy.nvim, loads config.options, calls lazy("plugins")
├── lua/config/options/
│   ├── init.lua          # Loads options → autocmd → keymaps → neovide → usercmd
│   ├── options.lua       # vim.opt, vim.g, leader key ",", clipboard (OSC52 fallback)
│   ├── autocmd.lua       # FileType, LspAttach, TermOpen, TextYankPost, last-loc
│   ├── keymaps.lua       # Core normal/visual keymaps
│   ├── neovide.lua       # Neovide scaling keys (conditional on g:neovide)
│   └── usercmd.lua       # :PrettyPrintJSON, :SudoWrite, :LazyGit, etc.
├── lua/plugins.lua       # Stub — intentionally empty, DO NOT populate
├── lua/plugins/*.lua     # 36 files, each returns a lazy.nvim spec (auto-discovered)
├── lua/config/
│   ├── mason/init.lua    # ensure_installed list for mason-tool-installer.nvim
│   ├── snacks/*.lua      # Per-module Snacks.nvim options (bigfile, picker, indent, etc.)
│   ├── dap/*.lua         # DAP adapter configs (go, python, sh)
│   ├── treesitter/init.lua # Parser list, highlight/indent enable
│   └── opencode/init.lua # OpenCode custom config + :OpencodeCommitMsg command
├── lsp/*.lua             # LSP per-server config overrides (ansiblels, lua_ls, powershell_es)
├── after/ftplugin/       # Filetype-specific settings (jinja2)
├── queries/jinja2/       # Custom treesitter queries (context.scm)
└── snippets/             # Ansible snippets (generated by snippet-converter.nvim + Python generator)
```

## Plugin Manager: lazy.nvim

Uses [lazy.nvim](https://github.com/folke/lazy.nvim) for plugin management. Locked at `lazy-lock.json` (in `.gitignore`).

### Spec pattern

Every `.lua` file under `lua/plugins/` is auto-discovered — each must return a lazy.nvim spec table (or list of specs).

**Lazy-loading triggers used in this config:**

| Trigger | Purpose |
|---|---|
| `lazy = false` | Load at startup (colorscheme, snacks, which-key, smart-splits, treesitter) |
| `event = { "InsertEnter", "CmdlineEnter" }` | blink.cmp completions |
| `event = { "BufReadPre", "BufNewFile" }` | gitsigns, persistence |
| `event = "VeryLazy"` | Non-critical UI (which-key opts) |
| `event = "BufReadPost"` | nvim-ufo, vim-matchup |
| `event = { "BufReadPost", "BufNewFile" }` | fidget, hardtime, none-ls |
| `cmd = { "Mason", "MasonInstall" }` | mason.nvim, mason-tool-installer |
| `ft = "ansible"` | ansible-vim |
| `ft = { "json" }` | vim-jsonpath |
| `ft = { "markdown" }` | render-markdown, vim-table-mode, markdown-preview |
| `keys = { ... }` | Key-triggered lazy-loading (dap, gitsigns hunk nav, opencode, trouble, outline) |
| `dependencies = { ... }` | Explicit dependency loading |

### Spec fields used

- **`opts`** — Table merged with defaults, implies `config`. Used for simple plugins.
- **`config`** — Function called when plugin loads. Used for complex setup.
- **`init`** — Always runs at startup. Used for setting `vim.g.*` flags before plugin loads.
- **`keys`** — Lazy-load trigger + keymap registration.
- **`build`** — Post-install hook (e.g., `:TSUpdate`, `make tiktoken`).
- **`dependencies`** — Ensures plugins load in order.
- **`priority`** — Load order for non-lazy plugins (higher = earlier).
- **`version`** — Pinned semver range (e.g., blink.cmp `"1.*"`).

### Adding a plugin

1. Create `lua/plugins/<name>.lua`
2. Return a spec table or list of tables
3. Optionally add to `lua/config/` for options if config is non-trivial
4. Run `:Lazy` to verify, or restart

**Never** edit `lua/plugins.lua` — it is intentionally empty and exists only as a lazy.nvim target.

## UI Framework: Snacks.nvim

[Snacks.nvim](https://github.com/folke/snacks.nvim) is a collection of quality-of-life plugins used as the primary UI layer.

### Enabled modules

| Module | File | Purpose |
|---|---|---|
| `bigfile` | `lua/config/snacks/bigfile.lua` | Disables LSP/syntax/folding for files >10 MiB |
| `explorer` | `lua/config/snacks/explorer.lua` | File explorer (replaces netrw), `<C-n>` toggle |
| `image` | `lua/config/snacks/image.lua` | Image rendering in buffers |
| `indent` | `lua/config/snacks/indent.lua` | Indent guides with scope+chunk indicators |
| `input` | `lua/config/snacks/input.lua` | Enhanced input dialog |
| `notifier` | `lua/config/snacks/notifier.lua` | Notification system (replaces `vim.notify`) |
| `picker` | `lua/config/snacks/picker.lua` | Fuzzy picker (files, grep, buffers, git, LSP, etc.) |
| `scratch` | `lua/config/snacks/scratch.lua` | Scratch buffers |
| `statuscolumn` | `lua/config/snacks/statuscolumn.lua` | Number/status column with fold+git integration |
| `terminal` | `lua/config/snacks/terminal.lua` | Terminal toggle |
| `words` | `lua/config/snacks/words.lua` | Word highlighting |

Disabled modules: `animate`, `dashboard`, `debug`, `lazygit`, `notify` (using notifier instead), `profiler`, `quickfile`, `scope`, `zen`.

Each module's config lives in `lua/config/snacks/<module>.lua` and is `require`d by `lua/plugins/snacks.lua`.

### Picker layout

Uses `preset = "telescope"` layout. Custom explorer actions: `my_confirm` (opens dirs in explorer, single file in pick_win), `my_tcd` (tcd from explorer). Input `<Esc>` closes, `/` toggles focus.

## Completion: blink.cmp

[blink.cmp](https://github.com/saghen/blink.cmp) provides LSP, snippet, path, and buffer completion. Configured in `lua/plugins/completions.lua`.

### Sources (in order)
1. `snippets` — Custom paths include `stdpath("config")/snippets` (Ansible snippets)
2. `lsp` — Min keyword length 3
3. `path` — Min keyword length 3
4. `buffer` — Min keyword length 3

### Keymaps
| Key | Action |
|---|---|
| `<CR>` | Accept, fallback to default |
| `<Tab>` | Select next / snippet_forward, fallback |
| `<S-Tab>` | Select prev / snippet_backward, fallback |
| `<C-b>` | Scroll docs up, fallback |
| `<C-f>` | Scroll docs down, fallback |

Selection: `preselect = false, auto_insert = false`. Documentation auto-shows on selection. Signature help enabled with rounded border. Disabled in snacks picker inputs (`vim.b.snacks_picker_input`).

## LSP & Tools: Mason Ecosystem

Uses [mason.nvim](https://github.com/mason-org/mason.nvim) + [mason-lspconfig.nvim](https://github.com/mason-org/mason-lspconfig.nvim) + [mason-tool-installer.nvim](https://github.com/WhoIsSethDaniel/mason-tool-installer.nvim).

- `mason.nvim` — Installs LSP servers, linters, formatters, DAP adapters to `stdpath("data")/mason/`
- `mason-lspconfig.nvim` — Automatically enables `vim.lsp.config` for installed servers; `automatic_installation = true`
- `mason-tool-installer.nvim` — Ensures the tool list in `lua/config/mason/init.lua` is installed. Run `:MasonToolsInstall`

### LSP servers installed

ansible-language-server, bash-language-server, docker-compose-language-service, gopls, jq-lsp, json-lsp, lua-language-server, powershell-editor-services, pyright, systemd-lsp, terraformls

### Per-server config overrides in `lsp/`

| File | Server | Overrides |
|---|---|---|
| `lsp/ansiblels.lua` | ansiblels | `filetypes = { "ansible" }`, `root_markers = { "ansible.cfg", ".ansible-lint" }` |
| `lsp/lua_ls.lua` | lua_ls | `runtime = "LuaJIT"`, globals `vim`/`require`, workspace library |
| `lsp/powershell_es.lua` | powershell_es | `filetypes = { "ps1", "psm1", "psd1" }`, `bundle_path`, OTBS formatting |

### Formatters & linters (none-ls)

[null-ls (none-ls)](https://github.com/nvimtools/none-ls.nvim) provides diagnostics and formatting:
- **Format**: black, prettier, shfmt (-i 4 -ci), shellharden, gofmt
- **Diagnostics**: pylint, markdownlint, golangci-lint, djlint, codespell
- **Completion**: spell

Disabled for files > 10 MiB.

### Treesitter parsers

bash, desktop, go, json, lua, markdown, markdown_inline, php, powershell, python, regex, yaml, diff, dockerfile, git_config, gitcommit, gitignore, jinja, jinja_inline, terraform, vim, vimdoc.

Highlight and indent enabled. Custom query at `queries/jinja2/context.scm` adds `@context` captures for Jinja2 folding.

## Conventions

### Code style
- **No comments in production code** unless explaining a non-obvious workaround
- Lua files use 2-space indentation
- Follow existing patterns when adding plugins (see any `lua/plugins/*.lua` for reference)
- Per-module config goes in `lua/config/<module>/` — never inline complex opts in plugin specs

### Plugin config patterns
- Simple plugins: use `opts = {}` (lazy.nvim auto-calls `require(plugin).setup(opts)`)
- Complex plugins: use `config = function() ... end`
- Startup-only setup: use `init = function() ... end` (runs before plugin loads)
- LSP override: create `lsp/<server>.lua` returning a table; configured via `vim.lsp.config`

### File organization
- `lua/plugins/` — One file per plugin or concern, each returns a lazy.nvim spec
- `lua/config/` — Sub-directories per concern (snacks, dap, mason, treesitter, opencode)
- `lsp/` — LSP server-specific config overrides
- `snippets/` — Custom snippets and generators (ansible)
- `queries/` — Custom treesitter queries
- `after/ftplugin/` — Vimscript filetype plugins

## No build/test/lint system

This is a pure Neovim configuration repository. There are no tests, no linters, and no build steps. Validate by opening Neovim and checking `:Lazy` status. The `lazy-lock.json` is gitignored.

## Deploy

`__deploy.sh` handles installation:
1. Detects Arch Linux (skips AppImage download if yes)
2. Downloads latest Neovim AppImage to `~/.local/bin/`
3. Symlinks `~/.config/nvim` → repository root
4. Backs up existing config if not already symlinked

## Big File Handling

Files > 10 MiB (`g:bigfile_size_limit`) trigger automatic performance optimizations:
- Disables matchparen, minianimate, backup/swap/undo
- Sets foldmethod=manual, disables statuscolumn, conceallevel, numbers, cursorline, colorcolumn
- Detaches all LSP clients, sets syntax=off
- Disables none-ls formatting/diagnostics
- Treesitter highlight disabled for files > 10 MiB
